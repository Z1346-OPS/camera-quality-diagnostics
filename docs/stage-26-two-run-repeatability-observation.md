# Stage 26 两个独立批次的白纸前后差值观察

## 目标与边界

核对 2026-09-30 的两个独立运行批次 `231ba1b4b1714c8abf2640f190308199` 与 `8cb1a0cfe81b4b13bf90e807594702d3`，观察各批次内首次白纸与恢复白纸的指标差值。本阶段只做描述性比较，不新增算法、阈值或相机故障结论。每个标签每批次只保存一帧；操作员对物体、摆位和光照只有事后近似描述，没有量化测量或逐帧照片。

## 程序与报告核对

- 两次终端日志都显示 `white_paper`、`colored_object`、`white_restored` 依次选择和保存，随后按 `q` 正常退出并释放摄像头。
- 两个会话 JSON 都记录配置编号 0、OpenCV 报告的 `DSHOW` 后端、帧尺寸 640×480。这不包含光照、纸张距离或自动曝光的测量。
- 对每个 `run_id`，`check_reports.py --run-id` 均返回 0：匹配 3 条、仅质量 0 条、仅颜色 0 条。分别导出配对 JSON 后，`validate_capture.py` 均返回 0，确认记录的三标签按帧号顺序各出现一次。JSON 产物留在被 Git 忽略的 `data/reports/`。

差值均为“恢复白纸减首次白纸”，由 `compare_white.py` 和 `summarize_white_runs.py` 只读计算。仅就这两次输入，亮度差值落在 +0.0 到 +0.3；这不是正常范围或合格标准。前一晚批次 `4d7de1d9475346adb5730a3a4768524e` 的亮度差为 +40.1，但跨日期条件未证明相同，不能把三批次直接合成一组稳定性结论，更不能推断差异由自动曝光造成。

## 条件与下一步

操作员事后描述：“两次运行的实际物体与摆位差不多，今天的光照比较稳定。”这句话已按 Stage 22 的方式分别保存在两个批次的 `camera_conditions_<run_id>.json` 中，来源标为 `operator_note`；未量化照度、纸张距离或具体位置，自动曝光状态未知。“差不多”和“比较稳定”不能替代可重复的条件测量，也不能证明每帧标签对应的真实物体。至少还需更多条件清楚的独立批次，才能更有依据地讨论重复性；故障阈值仍需另行标定。

易错点：①两次重新启动程序才是两个独立 `run_id`；一次运行按两次 `s` 不算。②同一批次的白纸前后差值小，不证明相机状态稳定。③标签顺序通过不自动证明现场物体正确。

练习：①为什么只比较两个新批次，不直接把前一晚批次并入同一范围？②`+0.0` 表示两帧亮度完全相同吗？③如果不清楚自动曝光设置，备注该怎么写？

四级掌握评价沿用项目标准：能看懂、能自己解释、能修改已有代码、能脱离原代码写类似逻辑。统计与文档由助手完成，用户独立掌握等级尚未评估。

面试可如实说：“我重新采集两个独立批次，分别用运行 ID 与帧号核对质量和颜色记录，再计算每个批次内白纸前后指标差。两次亮度差分别是 +0.3 和 +0.0；拍摄条件只有操作者近似描述、每场景只有一帧，因此我只把它当作初步观察，不设合格阈值。”
