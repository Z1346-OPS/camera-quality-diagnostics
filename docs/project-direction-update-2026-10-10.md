## 1. 这次想法为什么发生转变

用户提出：现在的项目有机会比最初的项目更有价值，希望将这一认识和方案更新记录下来。

最初的工作从摄像头连通性、采集和图像指标入手，逐步加入 CSV/JSON、原始帧留证及指标复算。这些成果使项目具备了采集、计算和追溯的基础，后续继续保留和复用。

随着项目加入本地图片、人工 ROI、二维码读码、独立答案核对和批量评测，图像指标开始关联一个具体任务：用户遇到标签读取失败时，能够比较不同处理方式，并检查结果与代价。

这次方向更新希望把这些能力组织成可运行、可演示、可复核的本地工具。预期价值主要来自以下方面：

| 价值来源 | 希望解决的问题 | 需要的证据 |
| --- | --- | --- |
| 具体业务任务 | 这张标签照片是否能读出二维码，结果是否匹配独立答案？ | 解码状态、原始字节比对、答案来源 |
| 有限方法对照 | 人工选区或内部降采样搜索是否改变结果？ | 相同输入下保留的各次尝试、配置和区域 |
| 实验评测 | 哪些改善、哪些退化、哪些仍然失败，增加多少时间？ | 逐样本结果、统计分母、排除规则和耗时 |
| 证据追溯 | 后续能否解释和复核一次结果？ | 原图哈希、清单、配置、代码与运行库版本 |
| 可读交付 | 用户能否方便地查看结果并演示完整流程？ | 离线报告及实际打开后的检查 |

“更有价值”在这里是用户对发展方向的判断和待验证的目标。项目是否节省排查时间、提高正确读取率，需要独立样本和实际使用证据，不能由页面完成或技术数量直接证明。

## 2. 当前目标与历史规划的关系

近期目标更新为：**标签图像质量分析与二维码读码排障辅助工具的本地可演示版本**。

目标用户是处理纸质标签二维码读取问题的调试、测试和技术支持人员；当前项目也用于学习输入校验、图像分析、实验设计和结果追溯。

当前优先完成的流程：

```text
准备原图、独立答案和样本清单
  → 校验输入与规范化
  → 整图 / 人工 ROI 的指标及二维码读码
  → 原基线与内部降采样搜索的对照
  → 独立答案核验与批量统计
  → 保存新的评测 JSON
  → 导出离线 HTML，查看明细、失败和限制
```

原有本地摄像头工具继续保留。摄像头保存原始帧后可作为本地分析的输入，但当前没有实时采集与二维码排障联动。

## 5. 实施前明确的细节

### 5.1 清单与采集信息

当前清单严格限制字段。新增设备、条件、ROI 确定规则时，采用可选字段并保持旧清单可读取；不能只修改样例，忽略校验器。

曝光、距离、设备或批次没有独立记录时保持未知。SHA-256 用于文件身份核对，不能证明实拍来源、答案真实性或访问权限。

### 5.2 分组、答案和冻结

先确定开发标签与测试标签，再安排实际采集批次。同一标签、同一批次、相同已知编码及其派生图遵循现有分组限制；不能仅更改编号来规避泄漏检查。

生成器二维码的独立答案应从原始生成材料中确认其实际编码内容。若二维码编码的是链接，答案为该链接的原始字节；链接目标页面的文字或图片不能代替它，也不自动访问链接。

参考成功定位或反复调整后获得的 ROI 属于探索性材料。独立测试所采用的人工选区规则应预先说明；人工耗时未测量时明确排除。

### 5.3 报告输入校验与统计一致性

导出只读取已有 JSON，不重新分析图片。检查格式版本、必填字段、类型、有限数值、文件大小、样本数量及汇总与明细的一致性。

复用公共统计规则进行一致性检查，避免维护另一套计算口径。合法的 `completed_with_errors` 结果可以导出，并突出失败；损坏、版本不支持或内部矛盾的报告明确拒绝。

目前配对统计将未知答案、输入错误和执行错误合并为一个排除数量。第一版如实显示现有口径；需要逐项列出排除原因时，在公共统计模块中统一补充并回归验证。

### 5.4 离线、安全与隐私

HTML 不联网，不依赖 CDN，不自动访问二维码链接。默认不嵌入原图、完整本机路径或二维码原始内容，也不将完整原始 JSON 放入隐藏区域或脚本。

只导出必要字段，对所有输入文本进行 HTML 转义；筛选逻辑不得将输入作为 HTML、脚本或命令执行。异常信息可能含路径，默认优先展示错误代码及安全摘要。

输出只新建，拒绝覆盖；导出失败明确报告。新增 HTML 产物的 Git 忽略规则若需调整，先备份现有配置并仅做必要修改。

### 5.5 正确性与耗时

有独立答案的失败样本保留在正确率分母；无答案的读出单独统计。答案不匹配保留为事实，并核查材料对应关系，不能直接断定是识别算法错误。

整图与 ROI、开发与测试、手机照片与截图及生成图分别统计。正确数、分母、改善、退化和排除依据同时展示。

区分原基线解码、基线加额外搜索的累计解码、端到端分析和报告导出耗时。当前中位数/P95 描述各样本计时分布；单个样本的一次计时不能证明性能稳定。重复计时不重复计入正确率分母。

## 7. 样本规模与完成标准

材料允许时，可准备约 10 个不同编码的标签，在正常、低光、反光条件下分别独立拍摄两次，形成约 60 张预实验照片。这是采样建议，不是已完成事实、统计充分性保证或工业认证要求。

采样前规划分组与批次；同一标签的多张照片具有相关性，照片数量不能当作独立标签数量。数量不足时如实报告现有规模，不凑数、不只保留成功照片。

工具验收与效果验收分开：

- **工具验收**：有效清单 → 新评测 JSON → 新离线 HTML 可完整运行，明细与统计一致，失败可查看。
- **效果验收**：独立答案及固定配置的新实拍实验已执行，样本划分与限制明确；无改善也可以形成真实实验结论。

5–7 天可作为投入条件合适时的本地演示版本估计；学习与面试准备可另留时间。打印、采集、基线问题或权限限制会影响进度，不为满足期限削弱验证。

最终完成标准：**输入有来源，处理可解释，结果有依据，失败不隐藏，记录可复核，演示能跑通。**
