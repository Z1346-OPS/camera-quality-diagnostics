# Stage 14 跨报告一致性检查

## 阶段目标和输入输出

只读检查两份带批次 ID 的报告，按 `(run_id, frame_count)` 找出共同记录、仅质量记录和仅颜色记录。输入为 `camera_quality_runs.csv` 与 `camera_colors_runs.csv`，输出为终端统计和未配对键，不修改报告、不判定摄像头质量。

## 关键流程与设计原因

分别读取两份 CSV，要求准确表头，逐行检查完整字段、规范的批次 ID、正整数帧号及重复键。构成两个键集合后求交集和差集。先完整校验两份输入，再打印结果，避免坏行导致“看似完整”的部分统计。

两份报告先后写入，不是原子事务；出现单侧记录有可能是写入失败，也可能因为两种报告功能启用时间不同。仅凭差集不能断定原因。旧无批次报告不纳入检查，也不回填历史 ID。

## 验证与实际结果

自动测试涵盖完全匹配、质量单侧、颜色单侧、错误表头、缺失文件、重复键和无效键。`python -m compileall -q src tests` 通过；新增检查器测试 `8 passed`，完整测试 `75 passed`。项目没有配置独立 build、lint 或类型检查。

2026-09-28 助手在项目真实报告上运行检查器，输出“匹配 1 条；仅质量 0 条；仅颜色 2 条”，退出码为 1。仅颜色的键为批次 `5df64a2060124fd89c8ff81143719db3` 的帧 480，以及批次 `980d092eddf048f2a096cda9bce3c30b` 的帧 338。这两批记录产生于质量报告带 `run_id` 之前；属于历史功能启用时间差，不能直接解释成保存失败。运行前后对两份 CSV 计算 SHA256，内容未变化。用户本人运行本阶段命令尚未验证，但程序已用真实报告做过运行时检查。

## 易错点与错误处理

- 退出码 0：全部键匹配；1：存在未配对记录；2：报告不存在或格式错误。出现 1 不代表摄像头故障。
- 应在摄像头退出后执行，避免读取正在追加的 CSV。
- 如果只看相同帧号而忽略 `run_id`，不同运行会错误匹配。
- 当前工具只核验关联键和行结构，不检查其他指标的值或时间戳。

## 学习重点、练习和面试表达

重点是复合键与集合交差。可选练习：解释帧号单独不可靠；解释单侧记录为何不等于保存失败；解释重复键为何应报错而不是合并。代码由助手实现，用户的四级掌握程度待自评。

面试可描述为：我为质量与颜色 CSV 增加只读一致性检查，通过批次 ID 和帧号识别匹配与单侧记录，明确区分数据完整性异常和摄像头故障结论。

## 运行

在项目根目录运行 `.\.venv\Scripts\python.exe -X utf8 .\src\check_reports.py`。程序不会修改原始 CSV；待用户看到实际输出后再决定下一阶段。
