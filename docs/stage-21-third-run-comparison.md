# Stage 21 第三次采集的跨批次观察

## 阶段目标

把已确认实际换上彩色物体的批次 `7bfd31a24dc64d96aa22311a78bf7200` 导出为配对 JSON，再与前两个完整批次比较白纸前后差值。输入为两份原始 CSV 和三个不同 `run_id` 的配对 JSON；输出是新批次 JSON、终端比较结果与本记录。本阶段不修改检测算法，不设故障或合格阈值。

## 关键流程与原因

先用 Stage 20 的按批次校验确认新批次质量与颜色记录按 `(run_id, frame_count)` 配对，再运行 `export_pairs.py` 创建 `data/reports/camera_pair_7bfd31a24dc64d96aa22311a78bf7200.json`。导出程序使用新建模式，目标已存在时不会覆盖。`compare_white.py` 计算本批次“恢复白纸减首次白纸”；`summarize_white_runs.py` 以三个不同的 `run_id` 各计一次，给出已输入批次的最小和最大差值。没有把误标的批次 `8b6fcfa1aac94d199769c320447d7050` 纳入彩色物体实验。

## 实际结果与验证

新 JSON 含 3 帧：667 `white_paper`、850 `colored_object`、1068 `white_restored`。按批次校验为“匹配 3 条；仅质量 0 条；仅颜色 0 条”。操作者确认中间换上了彩色物体，其他条件描述为“基本没变”；具体照明、距离和自动曝光状态没有量化或核实。

| 批次 run_id 前缀 | 白纸亮度差 | 清晰度差 | 对比度差 | 通道差差值 |
| --- | ---: | ---: | ---: | ---: |
| `e5125e7c` | +12.4 | +1.4 | −1.7 | −0.6 |
| `60f63b46` | +1.4 | −2.5 | +1.6 | +0.4 |
| `7bfd31a2` | −5.9 | −1.1 | −0.6 | −0.1 |

三个批次的观察范围分别为亮度 −5.9～+12.4、清晰度 −2.5～+1.4、对比度 −1.7～+1.6、通道差 −0.6～+0.4。亮度差正负都有，不能据此声称“恢复后一定变亮”或“相机不稳定”；前两批拍摄条件记录不足，第三批也只是口述“基本没变”。每个白纸标签各只有一帧，样本量与可比性均不足以标定阈值。

导出前后两份源 CSV 的 SHA-256 哈希一致，原始数据未被改写。真实 JSON 的单批次比较和三批次汇总均成功退出；完整项目测试 `110 passed`。项目没有单独配置 build、lint 或类型检查，且本阶段没有修改 Python 代码。摄像头实时采集由用户完成，助手只运行了报告处理命令。

## 易错点、练习与掌握评价

- 三个批次只是三个独立运行，不是三个严格同条件实验；最小—最大值不是正常参考范围。
- 场景标签由按键选择，不能只看 CSV 标签就断言画面内容正确；本次依据操作者确认。
- 白纸前后差值反映整条采集链的变化，不能仅凭它归因于相机硬件。

练习：①为什么 `8b6fcfa1` 不适合加入彩色物体比较？②亮度差出现正负号能直接证明什么、不能证明什么？③为什么跨批次汇总时每个 `run_id` 只计一次？

四级掌握评价沿用项目原标准：能看懂、能自己解释、能修改已有代码、能脱离原代码写类似逻辑。本阶段助手完成导出与汇总，用户的理解和独立操作能力仍需通过练习验证；没有代码修改，后两级本阶段未评估。

面试可如实说：“我用 `run_id` 关联质量与颜色记录，导出三次独立采集，并比较同批次的白纸前后差值。三次亮度差有正有负，但拍摄条件记录不充分、每个白纸场景只有一帧，因此我只把它们作为观察结果，没有设设备合格阈值。”

下一步若要研究重复性，应在更明确记录光照、纸张位置和曝光状态的条件下增加独立采集；不要为了凑样本重复输入同一 `run_id`。
