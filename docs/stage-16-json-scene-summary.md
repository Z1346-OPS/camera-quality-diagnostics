# Stage 16 配对 JSON 的场景汇总

## 阶段目标与输入输出

输入为 Stage 15 导出的**一个批次** JSON。输出为终端中的各场景样本数，以及亮度、清晰度、对比度、BGR 通道差各自的均值、最小值和最大值。本阶段不改变 JSON 或 CSV，不计算合格阈值，也不判断故障。

## 关键代码流程与设计原因

1. 读取 JSON，确认格式版本、批次 ID、记录数、帧号唯一性和场景标签。格式不完整就失败，避免从坏数据得到看似可信的统计。
2. 检查所有质量与颜色数值是有限数字，且不为负；有天然上界的亮度、比例、通道均值和通道差还要检查范围。这样不会把字符串、`NaN` 或明显越界值算进均值。
3. 按场景分组，对四个展示指标求均值、最小值和最大值。结果是**当前批次的描述性统计**，并未跨批次合并，也不是相机标定。

`count` 表示按 `s` 保存并成功导出的记录数，不是摄像头显示的帧数。连续几帧可能高度相关，不能因为记录数增加就把它们当成独立实验。

## 实际完成与验证

2026-09-29，真实 JSON 的运行输出是：`unspecified` 1 条，亮度 97.8、清晰度 48.9、对比度 26.4、通道差 1.7；四项范围的最小值与最大值都等于对应均值。没有 `white_paper` 场景记录，因此**尚无白纸参考范围**。聚焦测试涵盖分组、均值、只读、不支持的版本、错误记录数、重复帧号、非法场景、坏数值、统计溢出和缺失文件。完整测试 `98 passed`，语法检查通过，真实 JSON 命令退出码 0；项目未配置独立 build、lint 或类型检查。

## 易错点、练习与四级掌握

- 单条数据的最小值、最大值和均值必然相同，不代表画面稳定。
- `channel_spread` 小只代表整幅画面 BGR 均值接近；有彩色物体时不能直接推断“无偏色”。
- 场景标签由按键选择，不会由程序自动识别画面内容。

练习：①解释 `count=1` 为什么不能设阈值；②说出跨批次合并前需要确认哪些拍摄条件；③把场景从 `1` 切到 `2` 后预测汇总会怎样分组。

掌握评价：代码由助手完成；能看懂、能解释、能修改、能脱离原代码重写这四级均待用户实际练习，不代填。

## 面试表达与下一步

可如实说：“我对配对后的单批次 JSON 做场景分组和描述性汇总，并先校验数据完整性及数值范围。当前只有一条未指定场景的真实样本，不能用这些统计直接做工业相机的故障判定。”

下一步由用户在相对固定的光照、距离和相机设置下采集带标签样本：画面窗口按 `1` 选择白纸、`s` 保存，再按 `2` 选择彩色物体、`s` 保存，按 `3` 选择恢复白纸、`s` 保存，最后按 `q` 退出。应记录条件与实际 `run_id`，然后再导出并汇总；多次采样后才讨论参考范围。不要把不同光照和曝光条件的数据混成同一基准。

运行：在项目根目录执行 `.\.venv\Scripts\python.exe -X utf8 .\src\summarize_pairs.py .\data\reports\camera_pair_<run_id>.json`。
