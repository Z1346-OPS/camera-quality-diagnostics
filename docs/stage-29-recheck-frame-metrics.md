# Stage 29 留证图片与质量 CSV 的指标重算核对

## 目标、输入和输出

目标：对一张已保存的原始帧 PNG 重新计算亮度、欠曝比例、过曝比例、清晰度和对比度，并与相同 `run_id`、帧号的质量 CSV 数值比较。输入是运行 ID、帧号、两份 CSV 和 PNG；输出是每项的 CSV 值、PNG 重算值及是否一致，退出码 `0` 表示 5 项均一致，`1` 表示有不同，`2` 表示输入或读取错误。命令只读，不打开摄像头，也不显示画面。

```powershell
.\.venv\Scripts\python.exe -X utf8 .\src\verify_frame_metrics.py --run-id 9dd84fe9fbe24e32ab52ab0972e83ba3 --frame 306
```

## 为什么这样做

先用既有 CSV 核对模块验证批次与帧号，再按 Stage 27 的文件名寻找 PNG。使用项目当前的指标函数和采集阈值重算，并按 CSV 原有的一位小数格式比较字符串，避免把显示舍入误当成数值差异。留证 PNG 是无损格式；只要保存的是指标计算时的原始帧，且算法、阈值未变，这些结果应一致。

这只是**数值一致性检查**：两份文件可以恰好指标相同而内容不同；当前算法版本也可能与历史采集版本不同。任何不一致都应排查图片、CSV、算法与阈值，不能直接推断是相机故障。文件可解码也不证明白纸确实在镜头前。

## 实际验证与问题记录

- 合成图片测试覆盖完全一致、CSV 数值不同、PNG 缺失或无效、非法帧号、CSV 未配对及只读性。新增测试 4 个通过，全量测试 147 个通过；项目未配置独立 build、lint 或类型检查。
- 对真实批次 `9dd84fe9fbe24e32ab52ab0972e83ba3` 的第 306 帧执行命令，5 项均一致，退出码 0：亮度 121.6，欠曝 0.0，过曝 0.0，清晰度 7.0，对比度 7.1。程序只在内存中解码图片，没有展示用户画面。
- 本阶段没有更改采集流程或已有 CSV/PNG。测试使用可写工作区作为 pytest 临时目录，避免之前遇到的默认临时目录权限问题。

易错点：①比较的是保存后的一位小数，不是未舍入浮点数。②无图片时不能把“读取错误”说成“指标不一致”。③一致不等于画面标签正确。

练习：①为什么要用同一个 `run_id` 和帧号？②若只改了 `DARK_THRESHOLD`，哪一项最可能变？③若 CSV 与 PNG 数值不同，为什么不能直接说摄像头坏了？

面试可如实说：“我给每张留证图片建立了按批次和帧号的指标复核方法。用同一套函数重算 PNG 后，与 CSV 保存的一位小数比较；一次真实采集中 5 项一致。这个结果只能支持文件与指标的数值一致性，不能证明标签正确或定义合格阈值。”
