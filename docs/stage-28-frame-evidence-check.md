# Stage 28 按批次核对原始帧留证

## 目标与边界

输入一个 `run_id`，只读检查该批次质量与颜色 CSV 是否配对，以及每条配对记录是否有同一批次、同一帧号的可解码 PNG。输出分别统计可解码、缺失、空文件、无法解码的帧号。它不修改报告、不展示图片，也不识别白纸或判断摄像头好坏。

```powershell
.\.venv\Scripts\python.exe -X utf8 .\src\check_frame_evidence.py --run-id 9dd84fe9fbe24e32ab52ab0972e83ba3
```

退出码：`0` 表示本批次 CSV 配对且对应 PNG 均可解码；`1` 表示留证不完整；`2` 表示输入、CSV 或读取过程有错误。旧批次未启用 `--save-frames` 时会出现“缺失”，不能将其解释为程序保存故障。`可解码` 也不证明 PNG 内容就是标签声称的场景，更不证明拍摄条件一致。

## 真实运行与测试证据

用户于 2026-09-30 使用 `--save-frames` 采集批次 `9dd84fe9fbe24e32ab52ab0972e83ba3`：按 `1` 选白纸，在第 306 帧按 `s`，随后按 `q` 正常退出；终端报告已保存质量 CSV、颜色 CSV、会话 JSON 和原始帧 PNG。文件核对时，PNG 大小为 191661 字节，CSV 中同批次帧号均为 306。Stage 28 命令实际输出：可解码 1、缺失 0、空文件 0、无法解码 0，退出码 0。程序仅在内存中解码以检查文件，没有展示画面内容，也没有自动核实白纸是否在画面中。

对未启用图片保存的批次 `ae626d99f6d0471dacc00b4195ad702f`，命令实际输出缺失第 428 帧、退出码 1，展示了正常的“未留证”与“已留证”区分。自动测试覆盖有效、缺失、空文件、无法解码、未知批次、CSV 不配对和输入文件不被改写。

## 重点、易错点与练习

设计理由：用 `run_id` 区分不同启动批次，用帧号关联同次按 `s` 的数据；先核对两份 CSV，再检查图片，避免只看到一个 PNG 就误认为一组证据完整。局限：只能检查文件存在并可解码，不能证明它与 CSV 同一时刻生成，也不能验证操作员标签和拍摄条件。

易错点：①不带 `--save-frames` 的旧批次不应期待 PNG。②文件非空不等于能解码。③可解码不等于场景正确。

练习：①为什么不能只检查 PNG 文件名？②`缺失` 和 `无法解码` 的区别是什么？③为什么本检查不能得出“白纸测试通过”？

四级掌握评价沿用项目标准：能看懂、能自己解释、能修改已有代码、能脱离原代码写类似逻辑。程序和测试由助手完成，用户独立掌握等级尚未评估。

面试可如实说：“我让原始帧按运行 ID 和帧号与 CSV 对齐，并写了只读检查工具区分缺失、空文件和无法解码。真实摄像头批次中，一条配对记录对应一张可解码 PNG；工具不替代人工核对场景，也不把旧批次没有图片误判为摄像头故障。”
