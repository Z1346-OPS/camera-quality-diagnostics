# 文档 38：定时采集的 Linux 后端适配

日期：2026-10-19。范围：`src/run_capture.py` 的默认摄像头工厂。

## 问题与实现

原默认工厂固定请求 Windows DirectShow，即使 Linux 已能访问 `/dev/video0`，
也不能据此完成该入口的真实采集。现在 Linux 请求 `CAP_V4L2`；Windows 仍请求
`CAP_DSHOW`。非 Linux 平台保持原选择，未新增 macOS 等平台支持声明。
工厂与报告的 `camera.requested_backend` 共用同一选择函数，实际后端仍由设备查询。
不自动探测设备、不尝试其他后端、不重连。

`grab()/retrieve()` 失败传播、释放与首错语义保持不变，采样、指标、报告 schema
以及 implementation_version 均未改变。精确源码身份由报告的 source_sha256 记录。
旧交互入口 `main.py`、`camera_test.py` 不在本次 Linux 适配范围内。

## 验证范围

新增 8 个参数化集成用例：Windows/Linux × 正常、grab 失败、retrieve 失败、打开失败。
通过真实默认工厂连接假底层设备，核对 API 编号、摄像头编号、报告、原始像素、离线复核、
失败传播及恰好一次释放。旧源码 4 失败 / 4 通过；适配后 8 通过。
原报告契约测试显式固定 Windows 环境，保留全部原断言；Linux 字段由新增测试覆盖。

本机完整验证结果及命令见本轮 `data/reports/linux-backend-20261019-215733-b834dcd9/`。
该本地目录不随 Git 分发。完整测试首次因备份副本被 pytest 重复收集而失败；
备份移至仓库外后重新运行，失败日志保留。不删除或跳过产品测试。

第二次根目录测试另收集到历史 v3 诊断夹具，因缺少 `CQD_PROBE_PATH` 产生 35 个
设置错误；按其既有约定设置此变量后最终为 **532 passed / 4 skipped**（exit 0）：
产品用例 497 passed / 4 skipped，历史离线夹具 35 passed。四项跳过均为 Windows
创建符号链接的 WinError 1314；未调整权限。pip check、精确评测闸门均 exit 0。
现有真实任务的离线 CLI 复核为 consistent / 6 帧，输入摘要不变；CLI help exit 0。
没有配置独立 build、lint 或类型检查任务，也未在 Windows 打开真实摄像头。

Ubuntu 24.04 / Python 3.12 的既有 493 项测试及评测闸门通过，是适配前的用户终端证据。
本次 Windows 中模拟 Linux 平台的测试不等于 Linux 实机验证。更新后仍需在 Ubuntu
重新运行完整测试与评测闸门，然后用现有入口执行 10 秒 / 5 秒采集及离线复核。
没有 Linux 实机结果前，不声明 Linux 摄像头采集验收完成。
