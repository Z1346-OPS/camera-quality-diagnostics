# 主持人走查单

待执行真人走查。此包用于 1～2 位未参与开发的参与者，优先选择做过摄像头或扫码终端回归的人。只记匿名编号和相关经验。

## 开场前

给每位参与者一个匿名代号，如 `T01`（报告中的 `P01` 是问题编号）。为其准备一个同名空目录，将[匿名记录表](匿名记录表.md)复制为 `T01-记录.md`，由主持人填写。另两份文件 `T01-R1.md` 和 `T01-R2.md` 是参与者从助手导出的交接说明。

材料分两次交付。第一轮只发 [round-1](../round-1)，内含任务卡、`01.json` 和 `02.json`；第二轮只发 [round-2](../round-2)，内含 `03.json`。也可使用摄像头仓库 `data/reports/trial-c20feea-e0acf79/` 中对应的单轮 ZIP，逐轮发放并解压。主持人自行保管第二轮材料和整个 `host` 目录。参与者与接手人作答结束前，评分依据及参考导出仅供主持人查看。

这组三份报告的摄像头复现基线为 `c20feea`，本次核对的助手版本为 `dffff38`。从本机 PowerShell 运行以下命令，先把前两条 Git 命令打印的实际版本填入记录表。出现“选择已有报告”按钮即已就绪。每位参与者从新的助手窗口开始，两轮之间保持同一调查打开。

```powershell
git -C 'D:\Projects\Python\camera-quality-diagnostics' rev-parse --short HEAD
Set-Location -LiteralPath 'D:\AIProjects\projects\test_failure_investigator'
git rev-parse --short HEAD
.\.venv\Scripts\python.exe -B -X utf8 .\src\run_investigator.py
```

## 现场顺序

1. **第一轮作答。** 发第一轮材料时开始计时。参与者自行点“选择已有报告”打开 `01.json`，再点“添加操作后的结果”导入 `02.json`。照读任务卡：“这项异常能关闭吗？请写一句话交给下一位同事。”对方一作答，立刻在 `T01-记录.md` 的第一轮“首次原话”栏逐字记录并保存，再追问“你引用了哪份材料？下一步会做什么？”答错、表示“不知道”也原样记录。若先求助，先记卡点或求助原话，注明首次判断前得到的提示，提示后的回答另记。
2. **第一轮导出，随后发第二轮。** 让参与者点“保存说明”，在“预览说明”中点“保存”，另存为 `T01-R1.md`。主持人确认文件已落盘，在匿名表补齐第一轮用时、依据和求助情况，保存记录，**这时才交付第二轮材料**。若仅导出失败，保留已保存的原答，记“导出未完成”、报错和用时，仍可发第二轮。尚未作答就继续保管第二轮；若中止，记录原因。
3. **第二轮作答与导出。** 发 `03.json` 时重新计时。参与者在同一调查点“添加操作后的结果”追加它。照读同一句任务，先在记录表第二轮栏保存本轮原话，再询问判断有无变化、依据和下一步。另存为 `T01-R2.md`，填好用时及求助情况，保留第一轮原话和文件。
4. **独立接手（如有人选）。** 先只给接手人 `T01-R1.md`，问“你接下来要做什么？说明里的哪条证据支持你？”记下并保存回答后再给 `T01-R2.md`，问“你的判断有变化吗？依据在哪里？”记录实际补问和能否继续操作。没有独立接手人时，这一项记“未执行”。

## 评分依据

| 时点 | 能否关闭 | 可核查的依据 |
| --- | --- | --- |
| 第一轮 | 第 2 帧仍未解决 | 同一批次。`01.json` 的 `issues` 指向第 2 帧，摘要和指标无法核实。`02.json` 的完整 `declared_frame_counts` 与全部 `frames[].frame_count` 均为 `[1]`。需要晚于原异常、能核实该批次第 2 帧的复核。 |
| 第二轮 | 第 2 帧在本次核实范围内可关闭 | `03.json` 与原异常同批，具有不同的 `review_id` 和更晚的 `reviewed_at_utc`。帧集合为 `[1, 2]`，第 2 帧摘要匹配、五项指标的保存值和重算值逐对一致。原失败仍在历史中；硬件根因未知。 |

样例 [第一轮导出](after-round-1.md) 和 [第二轮导出](after-round-2.md) 来自助手实际读取本包三份文件后的会话。参与者完成前仅供主持人查看。

上面两份示例由原版本助手 `e0acf79` 导出。独立 AI 阅读时能理解第 2 帧仍未解决，但原第一轮说明无法从计数定位实际核实的帧。改名后的[第一轮参考导出](verified-frame-counts-round-1.md)写出 `verified_frame_counts=[1]`，[第二轮参考导出](verified-frame-counts-round-2.md)写出 `verified_frame_counts=[1, 2]`。主持人观察接手人能否独立找到核实集合、目标帧的原始字段定位和两次复核的 UTC 时间。

## 结束后交回

每人交回填好的 `T01-记录.md` 和实际保存的 `T01-R1.md`、`T01-R2.md`。若某轮未完成，在记录表写明原因，只交已有文件。可以在当前聊天附文件，或给出它们在项目内的位置。交回前检查文件名与自由文本，隐去姓名、联系方式、单位及本机私有路径；保留匿名原话、报告编号、帧号、引用字段和用时。
