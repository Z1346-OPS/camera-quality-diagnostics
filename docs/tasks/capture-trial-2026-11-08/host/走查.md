# 主持人走查单

待执行真人走查。此包用于 1～2 位未参与开发的参与者，优先选择做过摄像头或扫码终端回归的人。只记匿名编号和相关经验。

## 开场前

给每位参与者一个代号，如 `P01`，准备一个同名空目录，存放此人的两份交接说明。报告来自摄像头 `c20feea`；本轮使用助手 `9a7eb91`。本机两个 ZIP 位于摄像头仓库的 `data/reports/trial-c20feea-e0acf79/`，其中只含原走查材料。也可以分别复制本走查单上一级的 `round-1` 和 `round-2` 目录。主持人保管第二轮材料、本走查单和参考导出。

在本机 PowerShell 中运行以下两行。出现“选择已有报告”按钮即已就绪。让每位参与者从新的助手窗口开始，两轮之间保持这个窗口打开。

```powershell
Set-Location -LiteralPath 'D:\AIProjects\projects\test_failure_investigator'
.\.venv\Scripts\python.exe -B -X utf8 .\src\run_investigator.py
```

## 现场顺序

1. **第一轮。** 只交给参与者解压后的 `round-1`（任务卡、`01.json`、`02.json`）。从交材料时开始计时。请参与者自行点“选择已有报告”打开 `01.json`，再点“添加操作后的结果”导入 `02.json`。照读任务卡：“这项异常能关闭吗？请写一句话交给下一位同事。”先逐字记下回答，再请对方指出依据和下一步。让对方点“保存说明”，在“预览说明”里点“保存”，新建 `P01-R1.md`。
2. **发第二轮的时点。** 确认第一轮原话、用时及求助已记下，并看到 `P01-R1.md` 已保存，才发 `round-2.zip`。第一轮判断有误也原样保留。若仅导出失败，可另行记下参与者的第一轮交接原话，标明“导出未完成”和原因，再进入第二轮。参与者尚未作答时继续保管第二轮材料。
3. **第二轮。** 解压得到 `03.json`。继续同一调查，点“添加操作后的结果”追加它。再次照读同一句任务，单独计时，记录本轮判断、引用了什么、改变判断的理由或仍有的疑问。另存为 `P01-R2.md`。
4. **交给接手人。** 先只给另一位接手人 `P01-R1.md`，问“你接下来要做什么？说明里的哪条证据支持你？”记下回答后再给 `P01-R2.md`，问“你的判断有变化吗？依据在哪里？”记录实际补问和能否继续操作。没有独立接手人时，这一项记“未执行”。

## 评分依据

| 时点 | 能否关闭 | 可核查的依据 |
| --- | --- | --- |
| 第一轮 | 第 2 帧仍未解决 | 同一批次。`01.json` 的 `issues` 指向第 2 帧，摘要和指标无法核实。`02.json` 的完整 `declared_frame_counts` 与全部 `frames[].frame_count` 均为 `[1]`。需要晚于原异常、能核实该批次第 2 帧的复核。 |
| 第二轮 | 第 2 帧在本次核实范围内可关闭 | `03.json` 与原异常同批，具有不同的 `review_id` 和更晚的 `reviewed_at_utc`。帧集合为 `[1, 2]`，第 2 帧摘要匹配、五项指标的保存值和重算值逐对一致。原失败仍在历史中；硬件根因未知。 |

样例 [第一轮导出](after-round-1.md) 和 [第二轮导出](after-round-2.md) 来自助手实际读取本包三份文件后的会话。参与者完成前仅供主持人查看。

上面两份示例由原版本助手 `e0acf79` 导出。独立 AI 阅读时能理解第 2 帧仍未解决，但原第一轮说明无法从计数定位实际核实的帧。当前版本的[第一轮导出](verified-frame-counts-round-1.md)写出 `verified_frame_counts=[1]`，[第二轮导出](verified-frame-counts-round-2.md)写出 `verified_frame_counts=[1, 2]`。主持人观察接手人能否独立找到核实集合、目标帧的原始字段定位和两次复核的 UTC 时间。
