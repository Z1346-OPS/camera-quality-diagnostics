# 任务文件格式（最小版）

> 位置：`docs/tasks/<feature>.md`，一个任务一个文件，随代码进 git。
> 建立于 2026-10-12，基线 commit `528fafd`。
> **这是第一版，未经验证。跑过 3 个真实任务之后再改。**

## 为什么要有这个文件

分析、实现、验证三个环节必须读**同一份、版本化的输入**。
靠复制粘贴传递方案，出了问题无法回溯当时依据的是什么。

---

## 必填字段

### 1. 前提核验（Step 0，最重要）

**在写任何方案之前先回答：**

- [ ] 这个能力是不是**已经存在**？
- [ ] 现有测试是不是**已经覆盖**它？
- [ ] 现有代码是不是**已经满足**这条验收条件？

**结论只允许两种：**
- `已存在 / 已覆盖` → **任务作废，不进入实现**（在文件里写明证据，保留记录）
- `确认缺失` → 继续

**证据必须写成 `文件:行号` + 一句话结论。** 不允许"我看了下应该是没有"。

> 这一条是所有字段里回报最高的。实测第一次使用就作废了一个任务（见文末案例）。

### 2. 目标

一到两句话。可以有"我希望……"，但必须能对应到一句话能说清的行为变化。

### 3. 不改变（回归边界）

明确列出**不能破坏**的既有行为。这是回归测试的靶子，也是验证阶段的核验清单。

### 4. 验收条件（外部可核验）

每条必须能判定**"怎么算不通过"**。

**禁止：**
- ❌ `新测试通过` —— 测试由实现者写，等于实现者自己定 oracle
- ❌ `增加了 --xxx 参数` —— 这是需求，不是验收条件
- ❌ `功能正常工作` —— 无法证伪

**要求：**
- 每条给出**核验命令**
- **至少一条**拿"改动前的基线输出"做逐字节或逐字段比对（这就是外部 oracle）
- 涉及文件读写的，加一条"原文件未被修改"的校验（SHA-256 比对）

### 5. 基线快照

改动前的 commit hash + 需要比对的基线输出。
**oracle 必须来自这次改动之外** ——改动前的代码、独立数据集、或人工标注。

### 6. 分析区（只读，Codex 填）

- 影响文件（路径 + 为什么受影响）
- 方案
- 风险
- **前提核验结论**（第 1 步的证据）

### 7. 实现记录（执行者填）

改了什么、跑了什么、测试结果。**失败就贴输出，不要粉饰。**

### 8. 验证记录（验证者填）

- 逐条核对第 4 节的验收条件：第 N 条 → 通过 / 不通过 + 证据
- **主动找反例的结果**：尝试构造什么输入能让它坏？找到了什么？
- 明确写出"没找到反例"和"没尝试找反例"的区别

### 9. 观察（人填）

四个类别，一个问题一条：

| 类别 | 问什么 |
|---|---|
| A 理解 | 分析是否准确理解了现有代码？ |
| B 输出价值 | 方案是否比你自己读代码更有增量？ |
| C 执行质量 | 实现需要多少返工？ |
| D 验证质量 | 验证是否发现了人工发现不了的问题？ |

汇总到 `CodexKnowledgeBase/Observations/YYYY-MM-DD.md`。

## 案例 001：`--json-only` 输出模式（**任务作废**）

**提出日期**：2026-10-12
**结论**：**作废 —— 能力已存在，且已测试覆盖。**

### 原始需求

> 给 `src/analyze_label.py` 增加 `--json-only`，让程序只输出 JSON，不打印额外日志。

### 前提核验证据

| 检查 | 结果 |
|---|---|
| 实现是否已满足 | ✅ `src/analyze_label.py:137` 是**唯一**一处 stdout 写入：`print(rendered)`，`rendered = json.dumps(result, ...)` |
| 失败路径是否污染 stdout | ✅ 否。`analyze_label.py:135` 失败信息走 `file=sys.stderr` |
| 被 import 的模块是否 print | ✅ 否。`analyze_image.py:235` 的 `print` 在它自己的 `main()` 里，分析路径不调用；`label_analysis.py` / `metrics.py` 无 print |
| 测试是否已覆盖契约 | ✅ 是。`tests/test_label_analysis.py:16` 导入 `cli`，`:149` / `:362` / `:401` 三处对 `capsys.readouterr().out` 做 `json.loads` |

**没有需要关闭的输出。任务作废。**

### 这次作废产生的设计改动

原始流程的 Step 1 只有「目标 / 不改变 / 验收条件 / 风险」，
**没有"这东西是不是已经有了"这一项**，所以原本抓不到这种情况。

本次作废直接导致第 1 节「前提核验」被加进必填字段。

### 顺带记录的收益

- 省掉一整轮实现（改 CLI 参数 + 写测试 + 回归验证）
- 揭示了一件事：**只读分析阶段的首要价值是「否决不该做的任务」，而不是「产出方案」**
- 验证了这个流程在一个具体场景下能起作用 —— 但**样本量 = 1，还不足以说明流程有效**
