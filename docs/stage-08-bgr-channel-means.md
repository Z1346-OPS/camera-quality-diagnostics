# Stage 08 BGR 颜色通道均值

## 1. 阶段目标

分别计算摄像头彩色画面中蓝、绿、红三个通道的平均值，并实时显示 `B`、`G`、`R`。

本阶段只观察通道差异，为后续偏色分析建立数据基础；不设置偏色阈值，也不输出故障结论。

## 2. 输入和输出

- 输入：OpenCV 读取的 BGR 三通道彩色图。
- 输出：`(blue_mean, green_mean, red_mean)` 三个浮点数。
- 每个结果范围：`0.0–255.0`。

灰度图只有一个通道，不能用于比较颜色，因此函数会拒绝灰度图输入。

## 3. 为什么是 BGR 而不是 RGB

OpenCV 默认使用 BGR 通道顺序：索引0是蓝色，索引1是绿色，索引2是红色。如果误按 RGB 读取，就会把红色和蓝色含义颠倒。

## 4. 实现流程

1. 检查输入不是 `None`、类型是 NumPy 数组且内容非空。
2. 检查图像是 BGR 三通道。
3. 沿图像的高度和宽度两个方向求平均。
4. 按 B、G、R 顺序返回三个通道均值。
5. 在摄像头画面第六行显示结果。

## 5. 为什么不能直接判断偏色

彩色物体本身就会导致某个通道均值更高。相机自动白平衡、光源颜色、背景内容和曝光也会影响结果。因此，仅凭一次通道差值不能判断相机发生偏色；后续需要在已知中性目标和稳定光照下建立基准。

## 8. 易错点

- OpenCV 是 BGR 顺序，不是 RGB。
- 通道均值高可能来自画面内容，不一定是相机故障。
- 自动白平衡会让数值随时间变化。
- 白纸在彩色光源下三个通道也可能不同。
- 本阶段没有定义偏色阈值。
