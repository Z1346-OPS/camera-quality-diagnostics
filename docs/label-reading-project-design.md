## 1. 目标、用户与边界

服务于遇到纸质标签 QR Code 读取问题的视觉调试、测试和技术支持人员：保留输入证据，比较原图与有限处理、重拍后的读取情况，给出可复核的检查线索。首版按 JPEG/PNG、单张图片或一个人工选定 ROI、低照度与反光场景设计；模糊保留为边界案例。手机和普通摄像头实验不能证明工业相机交付能力。

首版不做生成式补码、通用照片修复、工业条码质量评级、相机硬件根因诊断、OCR、原生 App、实时视频、微服务、自训练大模型或 RAG。是否提高正确读取率、节省时间，由独立样本与耗时记录决定，不能写成预期必然结果。

## 3. 模块化单体与数据流

```text
本地图片 / 旧摄像头 / 后续手机上传
  → 输入校验与原件保存
  → EXIF、模式、通道规范化 → 人工 ROI
  → 同一基线图的指标与原图读码
  → 固定的灰度 / Gamma / CLAHE 分支及读码
  → 冲突检查、建议、人工复核、重拍关联
  → JSON / CSV / HTML 报告与历史

独立评测：冻结的样本清单 + 独立核实的真值 + 分组划分
  → 正确、未读出、错误、冲突、执行错误、改善、退化与耗时统计
```

分析核心只接收图像数据、ROI 和显式配置；不调用桌面窗口、Web 或数据库。旧摄像头入口继续可用。ROI 坐标以 EXIF 转正后的分析图为准；原图、分析图、缩略图、增强分支各有明确身份，全图与 ROI 的指标分别标记。展示用缩略图不替代分析图。每条分析记录要含数据格式版本、代码版本及未提交状态、配置、解码器版本、预处理、ROI、耗时和执行状态；未知拍摄条件保持未知，上传时间不能充当拍摄时间。

### 输入与输出约定

- 本地阶段按实际内容确认 JPEG/PNG、可解码性、模式、文件大小与像素数；超限、损坏、格式不支持、权限错误分别给明确状态。高像素手机图先维持明确拒绝，暂不悄悄缩小。以后若提供分析副本选项，需记录缩放并测试细小码读取影响。
- 原件按字节保存且不可静默覆盖；SHA-256用于内容核对。服务端图片 ID 与文件名由程序生成，不采用上传文件名作为存储路径。重新分析产生新结果，配置、ROI 或真值修订保留旧版本。
- 解码状态区分“读出”“未读出”“执行错误”“多目标/歧义”。只有独立已知答案进入评测后，才写“正确”或“错误”；无真值的读出不能称为正确。多分支冲突标为人工复核，不静默挑选最有利结果。
- 排查建议每条包含观察、数据证据、可能解释、下一步操作与不确定性。暗/亮比例不是已标定的曝光诊断；清晰度分数提高不证明读码改善。
- 正式结果保留未舍入的数值，页面可统一显示精度；不改写历史 CSV。对外报告不含凭据或内部绝对路径；网页转义编码文本，CSV 导出处理公式注入，不自动访问码内链接。

## 4. 数据、评测与实验协议

公开数据用于退化、参考图和质量方法边界；自采纸质 QR 标签用于读码业务验证。两条数据线单独汇报，公开自然图像不能替代标签证据。下载任何公开数据前核对来源、版本、许可证、体积、官方划分及使用条件；不上传私人照片到第三方。

清单逐样本记录：ID、来源与许可、原始哈希、标签/采集批次、设备与条件、参考图、独立核实的真实编码、合成退化参数、开发/测试组别。未知字段留空并说明来源，不能从待评测解码器输出生成真值。建议先询问能否获得约 10 个不同内容的纸质标签，再在正常、低照度、反光条件下分别独立拍摄至少两次，另留少量模糊图；这是预实验方案，不是已采样事实。

同一标签、重复采集及派生图按组划分；遵守公开数据官方划分。开发集调参数，固定后独立测试集只评估；反复用于调参的“测试集”应改称开发集并重新留出独立测试。增强和结果选择不读取真值。

有真值时逐项记录分子、分母与排除规则：正确、未读出、错误、冲突、执行错误、改善（基线不正确、处理后正确）、退化（基线正确、处理后不正确）及耗时中位数、P95和测量环境。比较原图直接读码、固定简单方法、候选流程及重拍原图。失败样本保留。PSNR/SSIM 仅在参考图对齐且尺寸、范围一致时使用，不替代业务正确率。

## 5. 存储、权限与运行边界

本地验证继续使用文件与 JSON，不迁移历史 CSV。服务阶段采用 PostgreSQL 与文件存储，核心关系为任务→多张图片→每图多次分析→每次多个处理分支，另记录用户/所有者、人工复核与修订、重拍、数据集、评测批次及错误事件。文件和数据库不共享原子事务：先临时写、校验、正式文件就位，再更新数据库状态；定义中断和残留检查、显式重试。上传状态区分接收中/就绪/失败，分析状态区分待执行/执行中/完成/失败/中断。服务重启后的遗留执行状态需可识别；重复请求要有幂等机制，不能只靠同名文件。

首个手机页面与接口同源，限制用户访问，不开放匿名公共上传。每次读取任务或文件都检查所有者；不接受远程 URL 抓图或任意服务器路径。服务端配置请求、图片、并发与存储限制；错误不暴露堆栈和凭据。公网部署前另做 HTTPS 与安全审查。短任务可先同步、限制并发；真正硬超时需可终止的进程，不能只让 HTTP 请求超时。需要时才引入队列。

原图、数据库及凭据不提交 Git。当前 `.gitignore` 只覆盖旧报告类型，新增正式存储目录前必须扩展。备份涵盖数据库、图片、配置和版本，隔离环境执行恢复检查；降级代码与数据库结构兼容性须验证，备份后新增数据可能丢失。开发阶段手机与电脑需同一网络且电脑开机；跨平台和部署支持只在实际验证后声明。
