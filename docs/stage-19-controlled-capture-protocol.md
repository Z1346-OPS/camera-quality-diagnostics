# Stage 19 受控采集方案（待执行）

## 为什么现在做

前两次真实采集的“恢复白纸减首次白纸”亮度差分别为 +12.4 和 +1.4，但两次的光照、纸张距离和相机摆放没有完整记录。`camera_test.py` 只指定摄像头编号并显示后端、实际画面尺寸；它没有设置或可靠记录自动曝光状态。因此不能把两次差值的上下限当成正常范围。本阶段先固定采集方法，不新增指标、不设故障阈值。

## 输入、输出和完成标准

输入：同一内置摄像头、白纸、一个彩色物体，以及每次运行前写下的拍摄条件。输出：每次独立运行的 `run_id`、三种场景各一条质量和颜色记录、运行日志与条件记录。**方案编写已完成；新的受控采集尚未执行。**

一次采集算完成，需要：

1. 终端显示摄像头成功打开，并记录编号、后端和实际分辨率。
2. 依次保存 `white_paper`、`colored_object`、`white_restored`，最后按 `q` 正常退出。
3. 用 `(run_id, frame_count)` 核对质量与颜色记录一一对应；缺项或报错要保留原样报告。
4. 条件记录不能空白；不知道的设置写“未知”，不能凭印象补写。

## 采集前固定条件

- 使用同一摄像头和桌面位置，尽量不移动摄像头。白纸放回同一位置、同一方向；可用桌面标记帮助复位。
- 尽量保持同一光源和遮光状态，不在采集中开关灯或改变窗帘。记录灯具、窗光等实际情况。
- 不同时修改摄像头编号、阈值或驱动设置。每次核对终端打印的后端与分辨率；不同配置的数据分开看。
- 当前程序未设置/记录自动曝光。未核实设备设置时填“未知”，不要写成“已关闭”或“已开启”。画面切换后，待预览视觉上趋于稳定再保存，不把短时间连续按多次 `s` 当作独立实验。

## 每次运行的步骤

在项目根目录运行 `.\.venv\Scripts\python.exe -X utf8 .\src\camera_test.py`。点击画面窗口并切换到英文输入法后：

1. 放白纸，按 `1` 选标签；画面稳定后按 `s`。
2. 换彩色物体，按 `2`，稳定后按 `s`；不要移动摄像头。
3. 把同一张白纸放回原位，按 `3`，稳定后按 `s`。
4. 按 `q`，确认终端报告正常退出并释放摄像头。保存 `run_id` 和条件记录。

下一次独立采集应重新启动程序以生成新的 `run_id`。多次按 `s` 只增加同一次运行中的记录，不等于多次独立采集。

## 条件记录模板

```text
run_id：
采集时间：
摄像头编号 / 后端 / 实际分辨率：
照明（灯具、窗光、是否变化）：
摄像头是否移动：
白纸位置与距离（未测就写“未测”）：
自动曝光状态（已核实开 / 已核实关 / 未知）：
本次与上一批的其他差异：
```

## 学习重点、练习和面试表达

重点是一次只尽量改变一个因素，并保留运行条件与原始输出。练习：①为什么两次 `run_id` 比同一次连续按两次 `s` 更适合作独立比较？②为什么“自动曝光未知”不能写成“自动曝光关闭”？③如果下一次改用了 `CAP_ANY`，应如何处理与旧批次的比较？

四级掌握评价：方案由助手整理；用户能否看懂、解释、执行并独立设计类似方案，待真实执行后评价。
