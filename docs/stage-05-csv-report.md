# Stage 05 单帧 CSV 质量报告

## 1. 阶段目标

在摄像头画面中按下 `s` 时，把当前帧已经计算出的质量指标追加保存到 CSV 文件。

本阶段只保存用户主动选择的单帧数据，不做连续自动记录、质量合格判定、JSON 报告、直方图分析或 RAG 诊断。

## 2. 输入和输出

- 输入：当前帧号、亮度、欠曝比例、过曝比例、清晰度和对比度。
- 输出：`data/reports/camera_quality.csv` 中的一行记录。
- 每行字段：记录时间、帧号和五项图像质量指标。

## 3. 为什么现在做

前四个阶段已经可以计算多项指标，但数据只显示在实时窗口中，程序退出后无法继续分析。CSV 报告把瞬时数据变成可以保留、比较和供后续诊断程序读取的结构化记录。

## 4. 实现流程

1. 摄像头读取一帧并计算全部指标。
2. `cv2.waitKey()` 获取键盘输入。
3. 用户按下 `s` 时调用 `append_quality_record()`。
4. 函数自动创建 `data/reports` 目录。
5. 第一次保存时写入表头和数据，后续保存只追加数据行。
6. 函数返回实际报告路径，摄像头程序在终端打印保存结果。

## 5. 为什么新建独立模块

`metrics.py` 只负责计算，`report.py` 只负责保存，`camera_test.py` 负责摄像头和按键流程。这样符合方案 B：保留现有程序，将新功能放进独立模块后逐步接入，也便于不打开摄像头就单独测试 CSV 写入。

CSV 使用 `utf-8-sig` 编码，使 Windows 上的 Excel 更容易正确识别编码；打开文件时使用 `newline=""`，避免 Windows 中产生多余空行。

## 8. 可能出现的问题

- 如果每次追加都写表头，CSV 中间会混入重复标题，因此保存前需要判断文件是否为空。
- 如果报告目录不存在，直接打开文件会失败，因此先自动创建父目录。
- 指标是按下 `s` 时当前视频帧的结果，不代表整段视频的平均质量。
- 报告是运行产物，已被 `.gitignore` 排除，不提交到 Git。
- 如果正在用 Excel 打开 CSV，Windows 可能锁定文件，导致程序无法追加写入。

## 9. 实际测试

测试日期：2026-09-21

本人运行摄像头程序并多次按下 `s`。实际文件包含一行表头和五行数据，说明后续保存会追加新行，不会重复写入表头。选取最后两次记录如下：

| 记录时间 | 帧号 | 平均亮度 | 欠曝比例 | 过曝比例 | 清晰度 | 对比度 |
|---|---:|---:|---:|---:|---:|---:|
| 2026-09-21T15:29:18+08:00 | 1858 | 111.7 | 0.0% | 0.0% | 35.8 | 34.4 |
| 2026-09-21T15:29:49+08:00 | 2814 | 147.1 | 0.0% | 0.0% | 6.0 | 10.3 |

两条记录时间相差 31 秒，帧号从 `1858` 增加到 `2814`，说明保存的是实时循环中不同时间的帧。第二个场景亮度更高，但清晰度和对比度更低，说明亮度高并不等于细节更多或对比度更强。

两次记录的欠曝和过曝比例都是 `0.0%`，表示没有像素落入当前的 `<=30` 或 `>=225` 阈值范围；它不表示曝光一定完全正确。
