# Stage 17 同批次白纸场景差值

## 阶段目标与输入输出

输入为一个批次的配对 JSON，且必须包含 `white_paper` 与 `white_restored` 两种手动场景标签。输出为两组保存记录数，以及亮度、清晰度、对比度、通道差的组均值和“恢复白纸减首次白纸”的差值。程序只读、不保存新报告、不判断故障或恢复效果。

## 关键流程与设计原因

复用 Stage 16 的 `summarize_pairs()`：它已校验 JSON 版本、批次 ID、记录数、唯一帧号、标签和数值。若缺少任一白纸标签，就明确失败，避免把缺失值当零。对每个指标取该标签下的均值，再计算 `white_restored - white_paper`。若将来每个标签有多条记录，此结果仍是**两个组均值之差**，不是逐帧配对差。

标签由操作者按键设置，程序无法证明画面确实为白纸，也不验证照明、距离、曝光参数完全相同。差值为正或负都只是观察结果，不能单独解释原因。输入 JSON 的场景顺序应由采集记录核对；通用比较命令本身只按标签分组。

## 易错点与练习

- 差值的方向必须固定为“恢复减首次”，否则正负号会反过来。
- 亮度差 +12.4 不代表曝光故障；相机自动曝光、光线变化或纸张摆放都可能影响结果。
- 一条记录不构成参考范围；首次与恢复场景都需要多次、条件可比的采集。

练习：①若首次亮度 120、恢复亮度 110，差值是多少？②两个标签各有 3 条时，程序比较的是逐帧差还是组均值差？③为什么不能把通道差下降解释为“偏色已修复”？
