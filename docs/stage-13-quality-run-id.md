# Stage 13 质量报告批次标识

## 目标和输入输出

同一次按 `s` 时，质量报告与颜色报告都记录相同的 `run_id` 和帧号。输入是摄像头当前帧的质量与颜色指标；输出分别是新的 `data/reports/camera_quality_runs.csv` 与已有的 `data/reports/camera_colors_runs.csv`。原始 `camera_quality.csv` 不改写。

## 关键流程与设计原因

摄像头程序在一次运行中只生成一个 `run_id`。按 `s` 时先调用 `append_quality_record(..., run_id=run_id)`，再调用颜色保存函数，两者接收同一个 ID 与 `frame_count`。报告模块检测 `run_id` 的 32 位十六进制格式，并在追加时核对表头。

为保护旧质量报告表头，新质量数据使用独立文件。程序其他调用者不传 `run_id` 时仍使用旧格式；以前的记录没有 ID，不能可靠地回填。后续若需要关联两种报告，应使用 `(run_id, frame_count)`，不能只用帧号或时间戳。

## 局限与易错点

- 两个 CSV 先后写入，不是一次不可分割的事务。若第二次写入失败，第一份报告可能已有记录；不能把“有相同键”当作保证两边都有数据。
- 人工场景标签仅在颜色报告中，质量报告没有重复保存标签。关联时先核对每个文件的表头和键，避免多对多重复。
- Windows 上查看程序占用 CSV 仍可能导致 `Permission denied`。关闭查看程序后再保存，不更改文件权限。
- `run_id` 是采集程序生成的随机标识，不包含个人凭据，也不用于构造文件名。

## 学习重点与面试表达

重点是同一次采集的两个指标文件如何确定属于同一帧：需要同时匹配批次 ID 和帧号。原始文件格式不改，新格式并行写入，可以保护历史数据。面试可如实表述为“为跨报告对照加入批次与帧号复合键，并通过摄像头按键保存核对了两份报告”。

可选练习：解释为什么帧号单独不够；描述第二份报告写入失败时如何判断部分保存；说出新旧质量报告的表头差异。代码由助手实现，用户四级掌握程度待自评。
