# Stage 27 可选保存原始帧证据

## 为什么做、输入与输出

此前 CSV 只有指标和手选场景标签，没有对应画面，事后无法核对镜头前实际物体。本阶段增加默认关闭的 `--save-frames` 选项；仅在操作员显式启用后，按 `s` 才额外保存当前帧到 `data/reports/camera_frame_<run_id>_<frame_count>.png`。输入仍是同一摄像头帧和按键；原有质量、颜色 CSV 及会话 JSON 格式不变。不启用时不保存任何 PNG。

## 实现思路与边界

开启留证时，预览使用当前帧的副本绘制指标文字，PNG 写入未叠字的原始帧；同一次按 `s` 的 CSV 与 PNG 共用 `run_id`、帧号。写图函数先校验关联键并编码 PNG，再用独占新建模式写入，已有文件不会被覆盖。图片保存失败会在终端提示“CSV 已保存”，不把失败说成成功，也不删除已写入的 CSV。

PNG 可能包含人脸、居住环境或其他私人内容，因此默认关闭、只保存在本机 `data/reports/`，现有 `.gitignore` 会忽略该目录下的 PNG；不要不经检查就分享图片。当前没有自动识别白纸或彩色物体的功能，图片只是供操作者事后人工核对，不是故障判定证据的充分条件。

```powershell
# 默认：只保存原有报告，不保存图片
.\.venv\Scripts\python.exe -X utf8 .\src\camera_test.py

# 明确选择后，按 s 时额外保存原始帧 PNG
.\.venv\Scripts\python.exe -X utf8 .\src\camera_test.py --save-frames
```

## 实际验证

- CLI `--help` 显示选项，退出码 0；默认流程测试确认未调用图片保存。
- 新增及相关聚焦测试 `11 passed`；完整项目测试 `138 passed`。覆盖 PNG 像素往返一致、同名不覆盖、无效关联键、编码失败、预览叠字但证据不叠字、图片写入失败时 CSV 仍保留并明确提示。
- 合成图运行时冒烟测试输出 `PNG roundtrip: (6, 8, 3) True`；源码语法检查通过；项目未配置独立 build、lint 或类型检查。
- 只用合成图和假摄像头验证，**没有打开真实摄像头或保存用户真实画面**。真实设备上的可选保存仍待操作员自愿启用后核验。

## 易错点、练习与掌握评价

- 不加 `--save-frames` 时绝不会因按 `s` 自动产生图片；既有采集习惯不变。
- PNG 与 CSV 的键相同，但 PNG 缺失并不表示 CSV 未保存；要看终端的单独提示。
- 留证图片只能帮助人工检查场景，不保证光照、纸张距离或自动曝光已被控制。

练习：①为什么预览要用副本画字？②为什么文件名需要同时有 `run_id` 和帧号？③图片保存失败后应检查哪两类文件？

四级掌握评价沿用项目标准：能看懂、能自己解释、能修改已有代码、能脱离原代码写类似逻辑。代码与测试由助手完成，用户独立掌握等级尚未评估。

面试可如实说：“我发现只有标签和指标无法事后核对真实画面，于是加入默认关闭的原始帧留证选项。启用后，程序按相同运行 ID 和帧号保存未叠字 PNG；测试验证了像素一致、文件不覆盖和失败提示。我没有把图片留证当成自动场景识别，也没有默认收集用户画面。”
