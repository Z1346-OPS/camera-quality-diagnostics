# Stage 18 跨批次白纸差值汇总

## 阶段目标与输入输出

输入为命令行显式列出的一个或多个配对 JSON，每份对应一次采集运行。输出为各批次的白纸前后差值；当至少有两个不同的 `run_id` 时，再输出已输入批次差值的最小值与最大值。程序只读，不设置阈值、不判断故障、不修改 CSV 或 JSON。

## 关键流程与设计原因

对每个 JSON 复用 Stage 17 的 `compare_white()` 校验和组均值差，再读取其已校验的 `run_id`。同一批次即使换了文件名，也只能计一次；重复 ID 会使整次汇总失败。每个批次贡献一个差值，避免保存帧数多的批次仅因记录更多而在跨批次分析中占更大权重。只有 1 个完整批次时不伪造范围，明确提示数据不足。

各批次应在摄像头程序退出、JSON 写完后再分析；不要在汇总期间修改输入文件。场景标签是人工指定，拍摄条件可比性也需要人工核对。这里的最小—最大值仅是输入样本的描述性范围，不是统计置信区间或工业相机合格标准。

## 实际完成与验证

2026-09-29，两个真实批次均各含 1 条首次白纸和 1 条恢复白纸记录。批次 `e5125e7c90fb4cfda143f2252b596fa0` 的亮度、清晰度、对比度、通道差分别变化 +12.4、+1.4、−1.7、−0.6；新批次 `60f63b46ade94b17ac5a7a79d269c39a` 分别变化 +1.4、−2.5、+1.6、+0.4。两个批次的差值范围分别为亮度 +1.4～+12.4、清晰度 −2.5～+1.4、对比度 −1.7～+1.6、通道差 −0.6～+0.4。新批次质量和颜色报告按帧号 549、718、951 完全配对，已导出 3 条 JSON；两份源 CSV 在导出前后哈希一致。真实文件重复输入时退出码为 1，明确报告重复 `run_id`。聚焦测试还用两份构造的独立批次验证范围计算，并覆盖单批次、换文件名重复 ID、缺少恢复白纸标签与空输入，`5 passed`；完整测试 `106 passed`，语法检查通过。项目未配置独立 build、lint 或类型检查。

本次只得到两次采集的**观察范围**，并未记录足够的光照、距离和相机自动曝光条件来证明两批可比；每个白纸标签也仅有一条记录，因此不能把这些上下限当作正常波动范围或设备阈值。

## 易错点、练习与四级掌握

- 两个文件不一定代表两个独立批次；要以 JSON 中的 `run_id` 去重。
- 范围的单位是**批次差值**，不是把所有帧混在一起求范围。
- 即使已有两个或更多批次，若光照、距离或自动曝光状态不同，也不宜直接合并解释。

练习：①为什么同一 `run_id` 的两个文件不能算两个样本？②批次 A 保存 2 帧、批次 B 保存 10 帧时，此处各贡献几个差值？③有 1 个完整批次时为什么不输出最小—最大范围？

四级掌握评价：代码由助手实现；用户“看懂、解释、修改、独立重写”四级的实际水平待练习后自评。

## 面试表达与下一步

可如实说：“我把每次采集作为独立批次，先计算同批次白纸前后差值，再按批次汇总，并用 `run_id` 防止重复计数。目前完成两次真实完整采集，差值方向和幅度并不完全相同；样本和拍摄条件记录还不足以建立故障阈值。”

下一步先固定并记录光照、摄像头位置、纸张距离和是否启用自动曝光，再增加独立完整采集批次。不要为了凑数量重复输入同一个批次。

运行：在项目根目录执行 `.\.venv\Scripts\python.exe -X utf8 .\src\summarize_white_runs.py .\data\reports\camera_pair_e5125e7c90fb4cfda143f2252b596fa0.json .\data\reports\camera_pair_60f63b46ade94b17ac5a7a79d269c39a.json`。获得更多批次 JSON 后，在命令末尾用空格追加其路径；只有一个路径时只输出该批次差值及数据不足提示。
